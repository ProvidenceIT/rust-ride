Create a mobile app (iOS/Android) for remote workout control, real-time metrics viewing, and ride history access. Connect to the desktop app over local network.

## Architecture Decisions

### Backend (Rust)
- Reuse existing tokio-tungstenite WebSocket infrastructure
- Extend existing mDNS discovery (mdns-sd crate)
- Leverage existing IPC handler patterns from daemon module
- Use existing LiveMetrics and SessionInfo types

### Mobile App
- **Framework**: React Native (cross-platform iOS/Android)
- **Language**: TypeScript
- **State Management**: Zustand (lightweight, TypeScript-friendly)
- **Navigation**: React Navigation v6
- **Service Discovery**: react-native-zeroconf

### Communication Protocol
- WebSocket for bidirectional real-time communication
- JSON message format (matches existing IPC patterns)
- PIN-based authentication
- 1Hz metrics streaming rate

## Completed Subtasks

### T001: Create companion module structure
- Created `src/companion/` module with mod.rs, types.rs, server.rs, handlers.rs
- Added module export to lib.rs
- Commit: fd8ff10

### T002: Define companion API types
- Verified comprehensive types already in types.rs from T001
- CompanionRequest: 12 command variants (Auth, GetSessionStatus, SubscribeMetrics, etc.)
- CompanionResponse: 11 response variants (AuthOk, AuthFailed, SessionStatus, etc.)
- CompanionEvent: 4 event types (Metrics, SessionStateChanged, IntervalChanged, Disconnecting)
- All types have Serde serialization with tag-based JSON encoding
- Commit: 68c5771

### T003: Implement companion WebSocket server
- Full WebSocket server using tokio-tungstenite
- Binds to 0.0.0.0 for LAN accessibility with configurable port (default 9876)
- Multiple concurrent client connections (up to max_connections limit)
- PIN-based authentication with 6-digit generated PINs
- Message routing to handlers for all request types
- Event broadcasting to subscribed clients for metrics streaming
- Local IP detection for LAN URL generation (with fallback methods)
- Graceful shutdown with client notification
- Added rand and tokio net dependencies to Cargo.toml
- Comprehensive unit tests for server lifecycle

### T004: Implement mDNS service advertisement
- Created CompanionMdnsAdvertiser in src/companion/discovery.rs
- Service advertised as '_rustride._tcp.local.' with TXT records
- TXT records include port, version (1.0.0), and protocol
- Integrated with CompanionServer start/stop lifecycle
- Mobile apps can auto-discover the companion server on LAN
- Commit: a6b908e

### T005: Implement metrics streaming handler
- Created MetricsStreamer component in src/companion/streaming.rs
- StreamingMetrics struct for aggregating power, HR, cadence, speed, distance, calories
- MetricsStreamer broadcasts at 1Hz via CompanionServer's event channel
- SensorEventProcessor adapter for processing SensorEvent::Data from SensorManager
- Added create_metrics_streamer() method to CompanionServer for easy integration
- Only authenticated subscribed clients receive metrics events (filtering in server.rs)
- Comprehensive unit tests for metrics updates and streaming lifecycle
- Commit: cea141c

### T006: Implement workout control handlers
- Implemented workout control handlers (pause, resume, skip, stop) in handlers.rs
- Full DaemonState integration via with_daemon_state() constructor
- Handlers validate session state and return proper error responses
- Comprehensive unit tests for all workout control scenarios
- Commit: 7a89c33

### T007: Implement ride history API handlers
- Updated handle_request() to accept database and user_id parameters
- Implemented handle_get_ride_history() with pagination support
  - Queries rides from SQLite database
  - Returns paginated RideSummary list with total count
  - Includes workout name lookup for structured workouts
  - Limit clamped to 1-100 for safety
- Implemented handle_get_ride_details() for single ride queries
  - Returns full RideDetailInfo with all statistics
  - TSS, IF, normalized power, avg/max HR, cadence
  - Proper error handling for invalid/missing ride IDs
- Added helper functions ride_to_summary() and ride_to_detail()
- Comprehensive unit tests for ride history operations
  - Tests for pagination, empty results, invalid IDs
  - Tests for database unavailable scenarios

### T008: Add companion server configuration

### T009: Add connection QR code generation
- Created src/companion/qr.rs module for QR code generation
- CompanionConnectionData: JSON-serializable connection info with url, optional pin, version
- CompanionQrCode: QR generator with ASCII and SVG output formats
- Uses qrcode crate with Medium (EcLevel::M) error correction
- Integrated with CompanionServer via generate_qr_code(), get_qr_ascii(), get_qr_svg() methods
- generate_pairing_qr_code() convenience function for standalone use
- QrCodeError for error handling
- Comprehensive unit tests included
- Commit: 291771c

### T010: Add session status endpoint
- Session status endpoint already fully implemented in handlers.rs (lines 103-173)
- handle_get_session_status() queries DaemonState for active session information
- Returns active: false, session: None when no active session
- For active sessions, returns SessionStatusInfo with:
  - session_id, session_type (free_ride or workout)
  - workout_name and workout_path for structured workouts
  - is_paused flag
  - elapsed_secs from session start
  - current_interval_index, total_intervals, current_interval_name
  - target_power_watts for ERG mode
  - interval_remaining_secs for workout intervals
- Comprehensive unit tests: test_get_session_status_with_active_workout, test_get_session_status_no_session
- All acceptance criteria verified and met
