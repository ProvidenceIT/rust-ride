### 1.3 - Add progressive discovery timeout (COMPLETED)
- Added progressive timeout types to `src/sensors/types.rs`:
  - `ProgressiveTimeoutConfig` - configuration for timeout behavior
    - `initial_scan_secs: 10` - aggressive initial scan period
    - `extension_period_secs: 5` - extension when sensors still being found
    - `max_total_secs: 30` - maximum total discovery time
    - `activity_window_secs: 3` - window for detecting recent activity
    - `idle_threshold_secs: 5` - time before stopping for idle
    - Preset configurations: `fast()`, `thorough()`, `disabled()`
  - `ProgressiveTimeoutState` - tracks discovery progress
  - `DiscoveryPhase` - Initial/Extended/Completed phases
  - `TimeoutDecision` - Continue/Extend/Stop decisions
  - `StopReason` - MaxTimeReached/IdleTimeout/Completed/UserRequested
  - `DiscoveryProgress` - summary struct for UI display with status_text() and progress_percent()
- Updated `src/sensors/manager.rs`:
  - Added `progressive_timeout_state` field to SensorManager
  - Replaced fixed timeout with progressive timeout in `start_discovery_timeout()`
  - Added `run_progressive_timeout()` async method that:
    - Monitors sensor discovery activity every 500ms
    - Extends scan when sensors are still being discovered
    - Stops early when idle for too long after finding sensors
    - Respects maximum total scan time (30s default)
  - Added `stop_discovery_internal()` helper method
  - Added public methods: `get_discovery_phase()`, `get_discovery_progress()`,
    `get_progressive_timeout_config()`, `set_progressive_timeout_config()`
- Updated `src/sensors/mod.rs` with new type exports
- Created comprehensive unit tests in `tests/unit/progressive_timeout_test.rs`
- Updated `tests/unit/mod.rs` with new test module

### 1.4 - Implement priority-based connection queue (COMPLETED)
- Created `src/sensors/connection_queue.rs` with:
  - `SensorPriority` enum - Primary (trainers/power meters) and Secondary (HR/cadence)
  - `ConnectionQueueEntry` struct - holds sensor with priority, preferred flag, and timing
  - `ConnectionQueue` struct - priority heap for ordering connections:
    - Preferred sensors connect first within their priority level
    - Primary sensors (trainers, power meters) connect before secondary
    - Secondary sensors (HR, cadence, speed) connect after all primary
    - FIFO ordering within same priority/preference level
    - Deduplication by device_id to prevent duplicate entries
- Updated `src/sensors/manager.rs`:
  - Added `connection_queue` field to SensorManager
  - `queue_sensor_for_connection()` - add sensor to queue with auto-priority
  - `queue_preferred_sensor()` - add preferred sensor with priority boost
  - `queue_all_discovered()` - queue all discovered sensors
  - `connect_next_in_queue()` - connect highest priority sensor
  - `connect_all_in_queue()` - connect all sensors in priority order
  - `connect_discovered_by_priority()` - convenience method for common flow
  - Helper methods: `connection_queue_len()`, `is_connection_queue_empty()`,
    `connection_queue_counts()`, `clear_connection_queue()`, `peek_connection_queue()`
- Updated `src/sensors/mod.rs` with connection_queue exports
- Created comprehensive unit tests in `tests/unit/connection_queue_test.rs`
- Updated `tests/unit/mod.rs` with new test module

### 2.3 - Implement reconnection state machine (COMPLETED)
- Created `src/sensors/connection_state.rs` with:
  - `ConnectionLifecycleState` enum - Disconnected, Connecting, Connected, Reconnecting
  - `StateTransition` enum - all valid transitions: Connect, ConnectionSuccess, ConnectionFailed,
    ConnectionLost, Disconnect, Reconnect, ReconnectionSuccess, ReconnectionFailed,
    ReconnectionExhausted, Reset
  - `InvalidTransitionError` - returned when invalid transitions are attempted
  - `ConnectionStateMachineConfig` - configuration with presets:
    - `default()` - auto_reconnect true, 5 max attempts, 1s initial delay, 30s max delay
    - `no_reconnect()` - auto_reconnect false
    - `aggressive()` - 10 attempts, 500ms initial delay, 15s max delay
    - `conservative()` - 3 attempts, 2s initial delay, 60s max delay
  - `ConnectionStateMachine` - per-device state machine with:
    - Valid transition enforcement (returns error for invalid transitions)
    - Time tracking (state entered time, connection duration)
    - Reconnection attempt counting with exhaustion detection
    - Statistics tracking (total connections, disconnections)
    - Intentional vs unintentional disconnect tracking
    - `stats()` method returns `ConnectionStateStats` for UI display
  - `ConnectionStateManager` - manages multiple device state machines:
    - Per-device state machine tracking
    - Bulk queries: get_connected_devices(), get_reconnecting_devices(), get_exhausted_devices()
    - State-based filtering: get_devices_in_state()
- Updated `src/sensors/mod.rs` with new exports
- Created comprehensive unit tests in `tests/unit/connection_state_test.rs`:
  - Basic state tests and display formatting
  - Configuration preset tests
  - Full connection flow tests (Disconnected -> Connecting -> Connected)
  - Reconnection flow tests (Connected -> Reconnecting -> Connected/Disconnected)
  - Reconnection exhaustion tests
  - Invalid transition tests
  - Statistics tests
  - ConnectionStateManager tests for multi-device tracking
  - Real-world scenario tests (trainer workout, HR failure, multi-sensor)
- Updated `tests/unit/mod.rs` with new test module

### 2.4 - Add persistent reconnection across app restarts (COMPLETED)
- Created `src/sensors/persistence.rs` with:
  - `SessionSensor` struct - stores sensor connection state:
    - device_id, name, sensor_type, protocol
    - connected_at, last_data_at timestamps
    - is_primary flag for primary sensors
    - was_healthy flag for connection health status
  - `ConnectionSession` struct - represents a connection session:
    - started_at, last_updated_at timestamps
    - sensors HashMap for tracking connected sensors

    - app_version for compatibility tracking
    - Methods: add_sensor(), remove_sensor(), reconnection_priority()

  - `ConnectionSessionManager` - manages session persistence:
    - JSON-based persistence at {data_dir}/sensor_session.json
    - Auto-save on sensor connect/disconnect
    - Session staleness detection (24 hour max age)
    - Reconnection target ordering by priority
    - Clean shutdown tracking for crash recovery
  - `PersistenceError` enum for error handling
- Updated `src/sensors/manager.rs`:
  - Added `session_manager` field to SensorManager
