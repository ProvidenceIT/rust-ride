## 2026-01-03 - Subtask 1.4 Complete: Auto-Reconnect Logic

### Completed:
- Added `auto_reconnect` and `reconnect_delay_ms` config options to `HidConfig`
- Added `DeviceReconnected` event type for auto-reconnect notifications
- Added `auto_reconnect_targets` HashMap to track devices that should be auto-reconnected
- Implemented `track_for_reconnect()` and `untrack_for_reconnect()` methods
- Modified `open_device()` to automatically track devices for reconnect
- Modified `close_device()` to remove devices from reconnect tracking (user explicitly closed)
- Updated monitoring loop to detect returning devices and auto-reconnect them
- Added configurable delay before reconnect attempt (default 1 second)
- Added unit tests for reconnect tracking and config

### Auto-Reconnect Flow:
1. When user opens a device via `open_device()`, it's tracked by identity key
2. If device is unplugged, it remains tracked for reconnection
3. When device is replugged and detected in monitoring loop:
   - Check if it's in reconnect targets
   - Wait for configured delay (default 1 second)
   - Attempt to reopen the device
   - Emit `DeviceReconnected` event on success
4. If user explicitly calls `close_device()`, device is removed from tracking

### Key Implementation Details:

- Requires both fan controller AND fan profile to be configured
- Speed step: +/- 10, clamped to 0-100 range
- Calls `fan_controller.set_speed(&profile_id, speed)` via async
- Errors (MqttError::NotConnected, etc.) gracefully converted to ActionError::ExecutionFailed
