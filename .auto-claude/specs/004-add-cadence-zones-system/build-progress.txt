## Implementation Summary

This implementation adds a complete Cadence Zones system to the rust-ride cycling computer application, following the existing PowerZones and HRZones patterns. The feature enables cadence-based training zone classification with visual indicators and zone change events.

### Phase 1: Core Cadence Zone Types (Complete)
- Created CadenceZoneRange struct in zones.rs (zone, min_rpm, max_rpm, color, name)
- Added CADENCE_ZONE_COLORS constant with 5 distinct colors (cyan/teal to magenta progression)
- Created CadenceZones struct with z1_low, z2_economy, z3_natural, z4_fast, z5_sprint zones
- Implemented Default trait with standard cadence zone boundaries:
  - Z1 Low: 0-75 RPM (recovery/climbing)
  - Z2 Economy: 76-85 RPM (efficient spinning)
  - Z3 Natural: 86-95 RPM (optimal cadence)
  - Z4 Fast: 96-105 RPM (high cadence drills)
  - Z5 Sprint: 106+ RPM (maximum cadence)
- Implemented get_zone(), get_zone_range(), all_zones() methods

## Architecture Decisions

1. **5-Zone Model**: Chose 5 zones (matching HRZones) rather than 7 (PowerZones) since cadence ranges are more constrained (typically 60-120 RPM)

2. **Zone Boundaries**: Used research-based standard boundaries:
   - Z1: 0-75 RPM for recovery/climbing
   - Z2: 76-85 RPM for economy/endurance
   - Z3: 86-95 RPM for natural/optimal
   - Z4: 96-105 RPM for fast/tempo
   - Z5: 106+ RPM for sprint/high-cadence drills

3. **Color Scheme**: Distinct cyan/teal to magenta progression that doesn't conflict with existing power (blue-red) or HR (green-red) zone colors

4. **ZoneType Enum**: Added ZoneType enum to zone_badge() for cleaner API compared to boolean flag
